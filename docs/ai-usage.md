> PNU 2026 AI Hackathon · Startup Track · Team C-07 핀핀이팀

## 1. 활용한 AI 도구

| 구분 | 도구 | 용도 |
|---|---|---|
| 제품 내 AI | **Gemini API (2.5 Flash-Lite)** | 비정형 금융상품 데이터 정규화, 금융 용어 풀이 |

## 2. 활용 범위

### 제품 내 AI (Gemini)
- **데이터 정규화:** 금감원 FSS·온통청년 API의 비정형 필드(가입대상, 우대조건, 납입한도 등)를 구조화된 JSON으로 변환. 규칙 기반 정규화를 먼저 적용하고, 보강이 필요한 필드만 LLM 호출
- **금융 용어 풀이:** 사용자 화면 전역에서 어려운 금융 용어를 쉬운 말로 설명

### 개발 과정 AI (Claude · Codex)
| 단계 | 활용 내용 |
|---|---|
| 기획 | 자격요건 필터링·적합도 정렬 기준 설계, 수익률 계산 로직 검증 |
| 설계 | 시스템 아키텍처, 시퀀스 다이어그램 구축 |
| 백엔드 | DTO·Entity·Repository 로직, 테스트 코드 작성 |
| 프론트 | React 컴포넌트 개발, 반응형 UI, UX 개선 |
| 데이터 | 공공 API 연동, 스키마 정규화 설정 |
| 배포 | EC2·Docker Compose 스크립트, 코드 리뷰 |

## 3. AI 생성 코드의 검증·수정 방식

### 제품 내 LLM 응답 검증
1. **스키마 검증:** Structured JSON 응답 포맷을 강제하고, `LlmEnrichmentValidator`에서 값 범위(나이 0~100, 금리 0~100% 등)와 키워드 유효성을 검증. 위반 시 예외 처리
2. **캐싱 및 버전 관리:** `prompt-version`·`schema-version`으로 LLM 응답을 DB에 캐싱. 로직 변경 시 버전을 올려 재처리 제어
3. **폴백 처리:** LLM 호출·검증 실패 시 기존 규칙 기반 정규화 결과를 유지해 서비스 안정성 확보
4. **쿨다운 정책:** 실패한 요청은 6시간 재시도 제한으로 API 비용·부하 방지

### 개발 코드 품질 검증
1. **아키텍처 가이드:** `CLAUDE.md`·`AGENTS.md`에 모듈 구조, 빌드/테스트 명령, 컨벤션을 문서화해 AI 도구가 일관된 코드 생성
2. **테스트 코드:** Testcontainers 기반 통합 테스트와 단위 테스트로 AI 생성 코드의 정확성 검증
3. **코드 리뷰:** AI 생성 코드를 팀원이 직접 리뷰 후 커밋. 비즈니스 로직·보안 취약점·에러 처리 중점 검토
4. **수동 검수:** AI가 생성한 금융 계산 로직(수익률, 기여금 연환산 등)은 실제 공시 데이터와 대조해 정확성 확인
