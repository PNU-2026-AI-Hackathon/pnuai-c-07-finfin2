## 2. 핵심 성과: LLM을 결합한 금융상품 데이터 수집

금감원 API의 가입대상·우대조건은 은행마다 자연어 표현이 달라 단순 규칙만으로 동일하게 비교하기 어렵다. 이를 해결하기 위해 `api/` Spring Batch 수집기에 **규칙 기반 + LLM 하이브리드 정규화**를 구현했다.

1. **원문 보존:** API 응답을 `ProductRaw`에 저장해 원문 대조와 재처리를 가능하게 했다.
2. **1차 정규화:** 코드가 상품명·은행·기본/최고금리·기간 등 명확한 값을 먼저 추출한다.
3. **LLM 보강:** 원문과 1차 결과에서 요약, 연령·소득·월 납입 조건, 가입 필수/제외 조건, 조건별 우대금리를 Structured JSON으로 추출한다. 기본/최고금리·기간·상품코드·은행·URL은 LLM 생성 대상에서 제외했다.
4. **검증·병합:** 규칙값을 우선하고 원문 근거와 `HIGH` 신뢰도를 만족한 값만 보수적으로 반영한다.
5. **저장:** 검증된 보강값 또는 실패 시의 규칙 결과를 공통 스키마에 저장해 정부·은행 상품을 같은 기준으로 추천한다.

`temperature=0`, 동시 요청 수가 제한된 비동기 배치, 원문·모델·프롬프트·스키마 버전 기반 캐시를 적용했다. `NORMALIZE_ONLY` 모드에서는 외부 API 재호출 없이 저장된 원문을 재정규화한다.

## 3. LLM 응답 검증·실패 대응

- **형식·값 검증:** JSON Schema로 응답 구조와 enum을 제한하고, 연령(`0~100`), 금리(`0~100%`), 음수 금액, 최소·최대 역전과 키워드 조합을 검사한다.
- **원문 근거 검증:** 소득 문구가 있을 때만 소득 상한을 수용하고, 예금의 월 납입한도와 근거 없는 자격 키워드 등 실제 오분류를 병합 가드로 제거한다.
- **폴백·관측:** 호출·파싱·검증 실패 시 규칙 결과를 유지한다. 실패는 6시간 재호출하지 않고 캐시 적중·호출·실패·쿨다운 수를 로그로 집계한다.
- **회귀 테스트:** 프롬프트·스키마·파서·검증·캐시·폴백·병합을 다루는 **45개 단위 테스트**로 오분류, 캐시 불일치, API 실패를 재현한다.
